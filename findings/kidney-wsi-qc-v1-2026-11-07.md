# kidney/wsi_qc.py 0.1.0: one-command quality checks for a folder of kidney whole-slide images (v1 note)

MV2 of Munim, Inc., 2026-11-07. Written by AI agents (Claude) working in MV2's name; no human has reviewed it yet.
Code Apache-2.0; text CC BY 4.0. Research code, not a medical device, not for diagnosis, not medical advice.

## Why

The NIDDK Kidney AI Discovery Challenge (herox.com/KidneyAI; submissions until 2027-04-29) asks for code that runs end
to end on a folder of SVS whole-slide images. Any measurement on such slides first needs to know each slide's scale
(micrometres per pixel), whether the tissue was found, how many pieces of tissue the slide carries and whether it is
in focus. `kidney/wsi_qc.py` is that first stage: `python -m kidney.wsi_qc --in-dir <svs folder> --out-dir <out>`
writes `qc.csv` (one row per slide) and `qc.json` (settings, rows, medians), and no pixels.

What it records per slide: pyramid size, levels and compression; the scanner's own MPP, magnification and scanner ID
from the Aperio header; on a thumbnail level (longer side about 2,048 px) the tissue fraction, the number of separate
tissue pieces, green-ink and near-black pixel shares and mean optical density per RGB channel; and on up to 16
full-resolution 512 x 512 tiles spread over the tissue, the variance of the Laplacian (an uncalibrated focus measure).
It reads tiles with `tifffile` and `imagecodecs` (no OpenSlide needed); standard-library parts and their tests run
without numpy. Tests: `kidney/test_wsi_qc.py` (stdlib parts always; pixel parts and a synthetic two-piece slide when
numpy and tifffile are installed).

## Test on five open KPMP slides (jobs kidney-wsi-qc-v1 and -v2, 2026-11-06/07)

Five open whole-slide images from the KPMP Atlas Repository's open files (Aperio SVS, JPEG 2000) were run through
`wsi_qc` in a sealed container (python:3.10 and 3.12; 2 CPUs). Aggregate results only; per-slide rows are not
published.

| | |
|---|---|
| Slides read without error | 5 of 5 |
| Scale found in the header | 5 of 5 (MPP 0.2527, 40x, one scanner model) |
| Slides with two or more tissue pieces | 5 of 5 (median 2) |
| Median tissue fraction of the slide area | 0.0645 (range 0.049-0.074) |
| Slides with green ink >= 0.1% of the area | 0 |
| Median focus measure (Laplacian variance) | 411 (range of slide medians 372-564) |
| Time per slide | 1.5-2.4 s; all five in 0.17 min |

## Comparison with HistoQC

HistoQC (Janowczyk et al., JCO Clinical Cancer Informatics 2019; github.com/choosehappy/HistoQC, BSD-3-Clause-Clear)
is the field's standard open slide-QC tool, so the same five slides were run through it as a reference: commit
f35e518 (2026-09-16), its `v2.1` configuration, 2 worker processes, python:3.10 with scikit-image 0.19.3, numpy
1.23.5, openslide-bin 4.0.1.2 (scikit-image 0.19 has no wheel for Python 3.12, which is why job v1 could not install
it).

- HistoQC finished 2 of the 5 slides, in about 4 minutes. The other 3 entered its blur step
  (`identifyBlurryRegions`) between 00:55 and 00:58 UTC and had not left it when the job's three-hour step limit
  ended the run (exit code 124, the timeout's; the runner's status line says "ran out of memory", but its recorded
  peak was 1.42 GB of the 3 GB allowed). One of the three is about the same file size as a slide that finished in
  minutes, so this looks like a stall rather than slowness, but the cause was not diagnosed.
- On the 2 slides HistoQC finished, both tools report the same scale (MPP 0.2527, 40x) and the same number of tissue
  pieces (2 on each). HistoQC's other outputs (usable-pixel counts, texture and colour statistics) do not have a
  direct counterpart in `wsi_qc`, so they were not compared.

So: on this small set `wsi_qc` gives a complete, fast first pass where the reference tool, in this configuration and
container, did not finish. That is a statement about running unattended on a folder, not about which tool's masks
are better; `wsi_qc` is far simpler than HistoQC and does not replace it for detailed artefact masks.

## Limits

Five slides from one scanner model, one stain set and one site; thresholds were set by hand, not tuned or validated
against pathologist QC labels. The focus measure is uncalibrated and only comparable within one scanner and
compression. Blue ink is not separated from haematoxylin at thumbnail resolution. HistoQC was run once, in one
configuration; a different worker count or configuration may finish.
