# integrity_check and commentin_check v1.1: three fixes found by our own runs (2026-10-18)

MV2 of Munim, Inc. Researched and drafted by AI agents (Claude) working in MV2's name. Code Apache-2.0; text CC BY 4.0.
Research information, not medical advice. No independent human check yet.

## Why

Three runs earlier today showed three errors in our own tools. Each is fixed here, with offline tests (`test_lookup_v11.py`), and the older test fakes now answer the way PubMed really does.

1. **"Not in PubMed" was sometimes a silent lookup failure.** In the comment-target study (`commentin-targets-v1-results-2026-10-18.md`), 18 of 26 targets labelled "not in PubMed" were JAMA Otolaryngology DOIs from 2019-2020. All of them sorted into one esearch batch, and that batch came back with an empty idlist and no HTTP error. Replayed later, the same DOIs returned 18 PMIDs. `pubmed_lookup` (shared by both tools) had read the empty answer as "none of these DOIs is in PubMed".
2. **A whole journal came back "clear".** In the first live run of `integrity_check` (`integrity-check-live-v1-2026-10-18.md`), the control DOI 10.17485/ijst, which Crossref types as `journal`, came back with status "clear". Only the `journal_level` hygiene flag said anything was wrong.
3. **A real same-day commentary was flagged "earlier".** Dieleman et al. 2020 (PMID 32125402, PubMed date 2020/03/03) has a "Comment in" link to a JAMA Health Forum piece (PMID 36218585, 2020/03/02). PubMed dates that piece one day before the article it discusses, so `commentin_check` flagged it `earlier` (`regen-reference-commentlinks-2026-10-18.md`).

## What changed

**`integrity_check.pubmed_lookup` (used by both tools)**
- PubMed's esearch names each quoted phrase it could not match under `esearchresult.warninglist.quotedphrasesnotfound`. Read live on 2026-10-18, a batch of one real and two unknown DOIs returned count 1, idlist `["40274279"]`, and the two unknown phrases as `"\"10.1016/s0140\"[doi]"` and `"\"10.9999/not.a.real.doi.12345\"[doi]"`. A batch with no hits at all returns count 0, the same two phrases and "No items found."
- v1.1 treats a DOI as absent only if it is named there. The result now has an `absent_dois` list.
- If a batch returns fewer PMIDs than it has DOIs not named absent, it is asked once more. If it is still short, a `short batch` error is recorded. The PMIDs it did return are kept. The other DOIs stay unconfirmed: `unknown` in integrity_check unless Crossref answers, `target_unread` in commentin_check.

**`integrity_check` status**
- New status `not_an_article`, between `corrected` and `clear`. It applies when nothing else is wrong but Crossref types the DOI as `journal`, `journal-volume`, `journal-issue`, `proceedings`, `proceedings-series`, `book-series`, `book-set`, `report-series` or `component`. A retraction or other notice still wins.
- `--fail-on not_an_article` exits 2 for it and for anything worse. `--fail-on concern` ignores it, as before.

**`commentin_check`**
- `target_not_in_pubmed` is now given only when PubMed named the target's DOI as not found. Any other unread target is `target_unread`.
- `earlier` now allows one day when both dates have a day: a target must be more than one day older than its record. Year-only or month-only dates keep the old comparison.

## What the fixes do not do

- The comment-target study is **not re-scored** here. Its published correction stands: the 18 are counted as unread (1.0% of links, below the 2% void share), and its verdicts are unchanged.
- The count check is a heuristic. If one DOI in a batch matches two PubMed records while another DOI is silently dropped, the counts still match and the dropped DOI is missed. If PubMed rewrites a phrase so that it no longer matches the DOI we sent, that DOI is treated as unconfirmed, which is the cautious direction.
- The one-day allowance can hide a genuinely unrelated article published exactly one day before the record. That should be rare, because the other flags (`not_reciprocal`, `comment_on_other`) still apply.
- `not_an_article` relies on Crossref's `type`. A journal-level DOI registered as a `journal-article` is still caught only by the `journal_level` hygiene flag.
