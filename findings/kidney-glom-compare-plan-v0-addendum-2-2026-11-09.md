## 2. Reading K (code: `kidney/kmask.py` 0.1.0, tests `kidney/test_kmask.py`)

- **Source.** The OME-TIFF annotation file of each slide's open KPMP "Seg_Masks_Features" v2 package. The feature
  workbook is used only for the consistency check in section 3.
- **Classes.** The channels named (case and spacing ignored) "non-globally-sclerotic glomeruli" (kind `glom`) and
  "globally-sclerotic glomeruli" (kind `gs`) in the file's OME-XML. If either is missing or appears twice, the
  slide's K cannot be produced (a missing slide under addendum 1).
- **Objects.** One object per distinct non-zero integer label in each of the two channels, as the package README
  defines ("each segmented unit in a layer is represented by a unique integer"). Labels are not split into
  connected pieces and not merged across channels.
- **Level read.** The finest pyramid level with at most 100 million pixels (height x width). For masks the size of
  the dry-run package this is level 2 (each pixel 4 x 4 level-0 pixels, about 1.01 um at 0.2527 um per level-0
  pixel). A glomerulus at the 2,000 um^2 floor covers about 2,000 pixels there.
- **Area.** The number of pixels carrying the label at that level.
- **Pixel size.** The OME-XML gives a unit but no value. The mask's pixel size is the slide's level-0 MPP (Aperio
  header of the package's own `.svs`) times level-0 width / read-level width, and is used **only** if the mask's
  level-0 width and height equal the slide's. Otherwise the slide's floor is not applied, its areas are not
  converted, and C3 is not graded (addendum 1).
- **Floor.** As in the plan: objects under 2,000 um^2 are not counted when the pixel size is known
  (`compare.count_k`, inclusive at 2,000).
- K and K_GS are then `count_k()`'s `k` and `k_gs`; C1-C4 are graded by `kidney/compare.py` 0.1.0 as published.

## 3. Consistency check (reported, not graded)

For each slide the number of labels in each glomerulus channel is compared with the number of data rows in the
feature workbook's `gloms` and `s_gloms` sheets (before the area floor). The report gives only how many of the
four slides match on both. A mismatch does not change K; it is reported as a limit.

## 4. The run

One job, CPU only: download the four packages (package ids stay in a private input file), run the offline tests of
`glom.py`, `compare.py` and `kmask.py` from the tagged release that carries this addendum, then `glom.py` on the
four slides, `kmask.py` on their masks and `compare.py` on both. A slide whose download or step fails for an
infrastructure reason is re-run and reported as such (addendum 1). Per-slide values stay local.

## 5. What will be published

Only `compare.py`'s aggregate output (slides within tolerance under the true and the shifted pairing, the pooled
count ratio, the pooled median-area ratio, whether the floor was applied, the globally-sclerotic note if
reported), `kmask.py`'s aggregate line (slides read, pixel size linked, workbook matches) and the run settings.
No per-slide count, area, name, package id or image.
