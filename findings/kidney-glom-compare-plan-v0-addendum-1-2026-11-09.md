Amends `findings/kidney-glom-compare-plan-v0-2026-11-09.md` (the plan). Written and published **before** the
stage-2 dry run (`kidney-glom-v3`) has produced any output and before any of the four graded slides has been
processed. When this was written, no glomerulus had been counted on any KPMP slide by us, and no KPMP mask had been
read. The predictions C1-C4 and their tolerances are **unchanged**.

## 1. A gap found while writing the grading code: C3 needs every glomerulus's area

C3 compares the **pooled** median area of our glomeruli (D) with the pooled median area of KPMP's objects (K).
`kidney/glom.py` 0.1.0, the version in the queued dry run, writes only each slide's median area, and a pooled median
cannot be computed from per-slide medians. So:

- `kidney/glom.py` 0.1.1 also writes `areas_um2`, the sorted area of every counted glomerulus, to the local
  `glom.json`. Nothing about counting changes: the same regions, the same 2,000 um^2 floor, the same settings
  (`kept_areas()` applies the same test as `summarize_regions()`, and a test checks they agree).
- The dry run keeps 0.1.0. D1-D4 do not use areas, so its grading is unaffected.
- The four graded slides will be run with 0.1.1 or later. Per-glomerulus areas from KPMP slides stay local; only
  the pooled ratio is published.

## 2. Rules fixed now for cases the plan did not cover

- **Missing slide.** If D or K cannot be produced for a graded slide, that slide counts as **outside** the C1
  tolerance, and C2, C3, C4 and the globally-sclerotic note are **not graded**: the run is reported as incomplete.
  A setup or infrastructure failure is not a result: it is fixed and the slide re-run, and the report says so.
  A slide on which the models run but find nothing gives D = 0, which is a result.
- **Boundaries.** All tolerances and ranges are inclusive (|D - K| = max(3, 0.25 x K) is within; a ratio of exactly
  0.80 or 1.25 holds C2). C2 and C3 are graded on the unrounded ratio and published to three decimals.
- **C2 with no KPMP objects.** If sum(K) = 0, C2 is not graded.
- **C3.** Not graded if any graded slide's K areas cannot be put in um^2, if any D lacks per-glomerulus areas, or
  if either side has no objects. K's 2,000 um^2 floor is reported as applied on all, none or some slides.
- **Globally-sclerotic note.** Reported only if the four slides hold at least 3 globally sclerotic objects in all;
  it names which of sum(K) or sum(K) - sum(K_GS) sits closer to sum(D), or "tie".
- **C4.** As in the plan: D of slide01 with K of slide03, 03 with 04, 04 with 05, 05 with 01. C4 holds only if the
  shifted pairing has strictly fewer slides within tolerance than the true pairing; otherwise C1 is reported as
  uninformative.

## 3. The grading code

`kidney/compare.py` 0.1.0 (standard library only) implements the plan and these rules: `grade()` takes local
per-slide values and returns aggregates only, and `check_aggregate()` refuses any output that names a slide. Its
tests use invented numbers only (`kidney/test_compare.py`). The part that turns KPMP's mask into objects
(`count_k()` takes (class, area in pixels) pairs) is format-specific. It will be written after the dry run describes
the package format, in a further dated addendum published before any graded slide is processed, as the plan says.
